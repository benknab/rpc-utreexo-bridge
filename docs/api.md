# Bridge REST and P2P interfaces

REST listens on `127.0.0.1:3000` by default (`API_HOST`). Responses use
`{"error":null,"data":...}`; errors set `data` to `null`.

## Processed chain and accumulator state

| GET resource | `data` |
| --- | --- |
| `/tip` | `{height, block_hash}` of the bridge's last completely processed block |
| `/block/{height}/hash` | Bitcoin display-order block hash |
| `/header/{hash}` | `{height, block_hash, hex}`; `hex` encodes the 80-byte Bitcoin header |
| `/acc` | `{height, block_hash, leaves, roots}` at the processed tip |
| `/roots/{hash}` | The same state object at a fixed historical block |
| `/roots` | Legacy array of current root hashes |

Heights refer to the bridge's processed chain, which can lag Core. Requests for
unprocessed or disconnected blocks return 404. Hash-keyed roots are retained
independently of proof pruning. `/roots/{hash}` now decodes the saved leaf count
and 32-byte roots; older versions incorrectly returned individual serialized bytes.

`leaves` counts leaves ever added, not the number still unspent. `roots` are ordered
from the largest tree to the smallest, including all-zero empty roots. There are
`popcount(leaves)` roots. All Utreexo hashes in REST are 64-character lowercase hex
in **raw digest order**. Block hashes and transaction IDs use Bitcoin display order.

## Capture a selected coin

`GET /leaf/{txid}:{vout}/proof` captures the full leaf, membership proof, and state
together, between block commits:

```json
{
  "error": null,
  "data": {
    "leaf": {
      "hash": "<raw leaf digest>",
      "block_hash": "<creation block hash>",
      "prevout": "<txid>:0",
      "utxo": {"value": 100000, "script_pubkey": "<hex>"},
      "block_height": 800000,
      "is_coinbase": false
    },
    "proof": {"targets": [1234], "hashes": ["<raw digest>"], "target_rows": 63},
    "state": {"height": 900000, "block_hash": "<proved-at block>", "leaves": 123456789, "roots": ["<raw digest>"]}
  }
}
```

The coin must be unspent at that local processed tip. No transaction index is
needed. Missing/spent coins return 404; an unavailable prover returns 503, and a
request timeout returns 504. The proof targets use the **fixed 63-row position space** used by Go
Utreexo and BIP183. A rustreexo 0.4 client must translate a promoted target's row
start into its actual forest size exactly once before verification. Hash bytes
must not be reversed when decoding bridge Utreexo hashes.

The leaf hash is the UtreexoV1 tagged SHA-512/256 digest of the full leaf data:
creation block hash, outpoint, `header_code`, and Bitcoin-serialized `TxOut`.
`header_code = (creation_height << 1) | is_coinbase`.

For delayed verification, independently fetch `/roots/{proved-at-hash}` and its
header from the verifier's chosen bridge. Check its accepted-chain binding. A
later spend does not invalidate membership at that earlier block. Archived
block-input proofs are not needed for this lookup.

## Existing proof and block resources

| GET resource | Behavior |
| --- | --- |
| `/leaf/{outpoint}` | Current unspent leaf data without a proof |
| `/prove/{leaf_hash}` | `{targets, hashes, target_rows, state}` for a raw leaf digest |
| `/tx/{txid}/outputs` | Full transaction and proof of all spendable outputs; fails if one is spent |
| `/tx/{txid}/unspent` | Unspent outputs and their proof |
| `/block/{height}` | `{block, proof, leaf_data}`, assembled from backend block + local block-input proof |
| `/batch_block/{height}/{n}` | Up to 16 combined records, starting at height |

Legacy `/prove`, transaction, and combined-block proofs retain rustreexo's
**actual-size** position space. Transaction proof responses include `state`.
Combined-block proofs prove spent inputs against the **parent** state. All proof
queries are read-only. Transaction-by-ID resources require Core's `txindex` for
arbitrary historical transactions; sync and outpoint proofs do not.

Combined-block resources return 410 when their proof is pruned or unavailable.
Core must still have the requested block to assemble a combined response.

## P2PV2

- BIP324 encrypted transport only, default port 8333 (`P2P_HOST`, `P2P_PORT`).
- `getdata(MSG_WITNESS_BLOCK)` retrieves a plain Bitcoin block from the backend.
  Fetch queues are bounded; excess requests receive `notfound` and can be retried.
- `getuproof`/`uproof` use short IDs 30/29. Targets use fixed 63-row positions.
  Proof requests read only local proof files. Missing proofs receive no `uproof`.
- `geturoot`/`uroot` use short IDs 36/35. The long `geturoot` command within P2PV2
  is also accepted. Roots use raw bytes, bound to the requested active block hash.
  The optional accumulator-of-roots proof is empty and `target` is zero.
- The old `getcfilters` filter-type-1 root exchange remains available.

See [storage and recovery](STORAGE.md) for pruning and advertised service bits.

## Compatibility checks

`tests/data/utreexo.json` was generated by `contrib/utreexo-vectors.go` against
Utreexod `e99c32c3fdb09a375450bd50c72cd7d2d2989792` and Go Utreexo `v0.18.0`.
Tests compare leaf hashes, roots, leaf counts, proof hashes and promoted targets
after spends, empty roots, and exact `uroot` bytes. Regenerating these vectors
requires running the Go tool from a matching Utreexod checkout.
